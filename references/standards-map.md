# 密评标准体系对照表（Standards Map）

> 用途：快速定位"某项检测 / 某个结论"在标准体系中的位置。
> ⚠️ 本表给出的是**框架级对应关系**。**具体测评项编号、测评点名称、评分权重、
> 符合率阈值一律以现行官方文本为准**（GB/T 39786-2021、GM/T 0115-2021、GM/T 0116-2021）。
> 现场使用前，请用官方标准文本逐条核对编号，禁止凭本表直接填写报告。

## 一、标准体系关系（先建立整体认知）

```
GB/T 39786-2021《信息系统密码应用基本要求》   ← 被评估方"应该达到什么"（基本要求）
        │  定义密码应用框架、测评项与目标
        ▼
GM/T 0115-2021《信息系统密码应用测评要求》   ← 测评方"按什么标准评"（测评要求）
        │  规定每个测评项的具体测评方法与判定准则
        ▼
GM/T 0116-2021《信息系统密码应用测评过程指南》 ← 测评方"怎么组织测评"（过程指南）
           规定测评流程、符合率计算方法与总体结论判定
```

一句话：**39786 定"要求"，0115 定"怎么评"，0116 定"怎么算结论"**。
密评报告中的结论（符合 / 基本符合 / 不符合）依据这三者的组合得出。

## 二、GB/T 39786 总体框架（层面 / 管理对照）

GB/T 39786 的密码应用框架可划分为**技术要求**与**管理要求**两大块：

| 大类 | 层面 / 管理 | 关注点（与 checklist.md 对应） |
|---|---|---|
| 技术要求 | 物理和环境安全 | 门禁、进出记录、视频监控、环境监测记录的密码保护 |
| 技术要求 | 网络和通信安全 | 通信身份鉴别、传输机密性 / 完整性、国密套件 |
| 技术要求 | 设备和计算安全 | 设备登录鉴别、远程管理通道、日志完整性、信任链 |
| 技术要求 | 应用和数据安全 | 用户鉴别、访问控制、数据存储 / 传输保护、不可否认性 |
| 技术要求 | 密钥管理 | 密钥全生命周期：生成、分发、存储、使用、更新、归档、销毁 |
| 管理要求 | 管理制度 | 密码管理制度、操作规程的制定与落实 |
| 管理要求 | 人员管理 | 密码管理人员职责、培训、考核与保密 |
| 管理要求 | 建设运行 | 密码应用的规划、建设、运行维护、供应商管理 |
| 管理要求 | 应急处置 | 密码安全事件应急预案、密钥泄露处置、恢复机制 |

> 行业习惯说法"四个层面 + 两项管理"（密钥管理 + 安全管理）是对上表的简化；
> 正式测评报告中的分类与编号，以标准官方文本的章节结构为准。

## 三、三维度判定对照（合规性 / 正确性 / 有效性）

每个测评项都要从三个维度判定，其含义与对应证据如下：

| 维度 | 含义 | 典型判定内容 | 对应证据类型 |
|---|---|---|---|
| 合规性 | 算法、技术、产品是否符合国家密码管理要求 | 是否使用国密算法；密码产品是否取得认证（商用密码产品认证） | 产品认证证书、算法配置、标准比对 |
| 正确性 | 密码功能实现与配置是否正确、按标准使用 | 密钥用途是否分离；算法参数是否合规；证书链是否完整 | 配置核查、功能验证 |
| 有效性 | 密码保护是否真实有效，而非"形式合规" | 数据是否确实密文存储 / 传输；鉴别是否确实生效 | 抓包、抽样验证、渗透性验证 |

> 只查"有没有配"（配置存在但无效）＝ 正确性 / 有效性不满足，常见判定为部分符合或不符合。

## 四、总体结论判定路径（GM/T 0116 过程）

```
逐测评项判定（符合 / 部分符合 / 不符合 / 不适用）
        │
        ▼
按 GM/T 0116 规定的符合率计算方法汇总（各测评项按权重计分）
        │
        ▼
对照总体结论阈值 → 符合 / 基本符合 / 不符合
        │
        ▼
输出报告 + 关键短板说明 + 整改建议
```

- **符合率计算**：以 GM/T 0116 给出的公式与权重为准（不同等级系统的测评项与权重不同）。
- **关键点**：存在"红线项"（如默认口令、明文密钥、无认证的密码产品等）时，即使符合率达标，也可能被直接判定为不符合——具体规则以标准文本为准。

## 五、与等保测评的关系

| 对比项 | 等保测评 | 密评 |
|---|---|---|
| 依据标准 | GB/T 22239-2019 等 | GB/T 39786-2021 等 |
| 范围 | 整体信息安全 | 密码应用专项 |
| 关系 | 等保对密码应用提出要求 | 密评专项评估密码应用是否达标，二者衔接 |

新建系统遵循"**三同步一评估**"：密码应用与系统**同步规划、同步建设、同步运行**，并**定期开展密码应用安全性评估**。处理等保测评报告中的密码相关章节时，可复用本技能的框架与判定思路。

## 六、使用注意事项

1. **编号必须核实**：本表不列具体测评项编号（避免误导），使用前对照官方标准文本补齐。
2. **等级差异**：二级 / 三级 / 四级系统的测评项范围与权重不同，检测前先确认被测系统等级。
3. **行业特性**：金融、政务、能源等行业可能有额外的行业性密码应用要求（如金融数据分类分级），需结合行业监管文件补充。
4. **时效性**：标准可能修订，使用前确认所用版本为现行有效版本。
