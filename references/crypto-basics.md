# 国密算法速查与常见误用

> 用于密评判定时的算法参考。参数以国家密码管理局发布的算法标准（GM/T 系列）为准。

## 国密算法速查表

| 算法 | 类型 | 密钥 / 输出 | 标准 | 典型用途 | 常见误用 |
|---|---|---|---|---|---|
| SM2 | 非对称（椭圆曲线） | 密钥 256 位 | GM/T 0003 | 数字签名、密钥交换、数据加密 | 与 SM4 混淆；签名私钥用于加密 |
| SM3 | 杂凑 | 输出 256 位 | GM/T 0004 | 完整性校验、消息摘要、配合签名 | 把摘要当加密用 |
| SM4 | 对称分组（128 位分组） | 密钥 128 位 | GM/T 0002 | 数据加密（存储 / 传输） | 使用 ECB 模式；密钥硬编码；IV 重用 |
| SM9 | 标识密码（双线性对） | 无证书体系 | GM/T 0044 | 基于标识的签名与加密 | 与 SM2 的证书体系混淆 |
| ZUC | 序列密码 | 密钥 128 位 | GM/T 0001 | 无线 / 流式数据加密 | 密钥流重用（严重） |

## 用途分离原则（判定时的核心）

- **加密**（机密性）、**签名**（不可否认性 / 身份）、**杂凑**（完整性）是三种不同目的，
  密钥必须分开，不能一把密钥通吃。
- 数字信封场景：SM2 加密会话密钥 / SM4 加密数据 是常见合规组合。
- 身份鉴别与数据加密不要混用同一证书 / 密钥。

## 安全强度参考（判定"是否过弱"时用）

| 算法（国密） | 对应国际算法（同等安全强度） |
|---|---|
| SM2-256 | RSA-2048 / ECC-224 以上 |
| SM3-256 | SHA-256 |
| SM4-128 | AES-128 |
| SM9 | 基于标识的 ECC 体系 |

## 合规红线（出现即高风险）

- MD5 / SHA-1 用于数字签名或完整性关键场景
- DES、3DES（弱）、RC4、TLS 1.0 / 1.1 等陈旧协议
- 随机数重用（IV / nonce 重用）—— 对称加密与序列密码都会因此被破解
- 加密模式使用 ECB（相同明文 → 相同密文，泄露模式）
- 用"自定义加密算法"代替国家批准算法且无合规依据
- 自研密码模块未做合规评估、无认证

## 判定时的取证思路

- 用抓包 / 浏览器或客户端探测实际协商的 TLS 套件（确认不是"配置写国密、实际走国际算法"）
- 检查密钥与 IV 的生成、存储位置（是否明文、是否与数据同库）
- 检查密码产品是否有《商用密码产品认证证书》，证书是否在有效期内、型号是否在目录内
