# 密评高频问题与整改建议

> 现场检测中最常发现的问题。按"影响结论的程度"排列：高 → 中 → 低。
> 整改建议要落到具体动作，写报告时可直接引用。

## 高风险问题（直接影响测评结论）

| 问题 | 典型场景 | 影响 | 整改建议 |
|---|---|---|---|
| 默认口令 / 弱口令 | 设备、数据库、管理后台仍用出厂默认口令 | 身份鉴别形同虚设 | 立即修改强口令，启用口令复杂度与失败锁定策略 |
| 密钥明文存储 / 硬编码 | 源码或配置文件里写死密钥 | 密钥泄露即全盘失守 | 密钥移入密码机 / KMS / 安全存储，程序运行时动态获取 |
| 弱算法 | MD5 / SHA-1 签名、DES、RC4、TLS 1.0/1.1 | 加密可被破解，不合规 | 替换为国密 SM2/SM3/SM4 套件，升级 TLS 配置 |
| 密码产品无认证 | 自研或第三方产品无《商用密码产品认证证书》 | 产品合规性不成立 | 换用有认证的产品，或推动产品完成认证 |
| "假加密" | 字段名是加密，实际存明文；或加密后密钥与数据同库 | 有效性不成立 | 实测验证加密有效性，密钥与数据分离存储 |

## 中风险问题（常见、影响部分测评项）

| 问题 | 典型场景 | 整改建议 |
|---|---|---|
| 密钥长期不轮换 | 同一密钥使用数年无更新记录 | 制定并执行密钥轮换周期（按标准要求），留痕 |
| 用途未分离 | 加密、签名、认证共用同一密钥 / 证书 | 按用途拆分密钥体系，各司其职 |
| TLS 未用国密套件 | 传输加密走国际算法套件 | 配置国密 SM2/SM4 的 TLS 套件（如 TLCP / 国密 TLS） |
| 日志无完整性保护 | 日志明文存储、可被篡改 | 日志加 SM3 摘要链或签名，保证真实性完整性 |
| 视频监控 / 门禁记录无密码保护 | 物理层记录可被篡改 | 对记录做完整性校验（摘要 / 签名） |
| 密钥备份与恢复无保护 | 备份介质明文、无访问控制 | 备份加密存储，恢复流程有审批与记录 |

## 低风险问题（管理类，影响安全管理层面）

| 问题 | 典型场景 | 整改建议 |
|---|---|---|
| 密码管理制度缺失 | 无密钥管理规程、无应急响应预案 | 建立制度文件并培训、演练 |
| 人员职责不清 | 密钥管理员 / 审计员同一人兼任 | 职责分离，权限最小化 |
| 供应商维护缺位 | 密码设备维保过期、无升级渠道 | 明确供应商责任，定期巡检升级 |

## 写整改建议的要点

1. **先高危后一般**：报告中按高 → 中 → 低排序，高危项写清可能导致的后果。
2. **建议可落地**：每一条都要是"改什么、怎么改、谁来改"的具体动作，而不是"加强管理"这种空话。
3. **区分技术与制度**：技术问题给配置 / 方案级建议；管理问题给制度 / 流程级建议。
4. **给出优先级与时间**：如"高：一个月内完成密钥替换与口令整改"。
